# Figma UI MCP Bridge — Kiettt8 Custom Edition

This guide installs the MCP server from source, registers the local Figma development plugin, and explains how to develop the custom light UI.

Repository: `https://github.com/kiettt8-product/figma-ui-mcp`

## 1. Requirements

- macOS, Windows, or Linux with Node.js 18 or newer.
- Figma Desktop for the current localhost bridge.
- An MCP-compatible client such as Codex, Claude Desktop, Cursor, VS Code, or Windsurf.
- Git.

Check the required commands:

```bash
node --version
npm --version
git --version
```

## 2. Clone and install

Choose a permanent development directory. Do not use a temporary download folder because Figma stores the exact manifest path.

```bash
git clone https://github.com/kiettt8-product/figma-ui-mcp.git
cd figma-ui-mcp
npm install
```

Configure any detected MCP clients:

```bash
npm run setup
```

The wizard supports Codex, Claude Code, Claude Desktop, Cursor, VS Code, and
Windsurf. It uses absolute paths, preserves unrelated MCP entries, and creates
a timestamped backup before changing an existing config.

For unattended setup:

```bash
npm run setup -- --client codex,cursor --yes
```

Preview changes without writing files:

```bash
npm run setup -- --client all --dry-run
```

Verify the local server:

```bash
node server/cli.js --version
```

## 3. Configure the MCP client manually

Use this section only if the setup wizard cannot update the client. Use an
absolute path to `server/index.js`.

### Codex

Add this to `~/.codex/config.toml`:

```toml
[mcp_servers.figma-ui-mcp]
command = "node"
args = ["/ABSOLUTE/PATH/TO/figma-ui-mcp/server/index.js"]
```

### Claude Desktop, Cursor, VS Code, or Windsurf

Add the server to the client's MCP JSON configuration:

```json
{
  "mcpServers": {
    "figma-ui-mcp": {
      "command": "node",
      "args": [
        "/ABSOLUTE/PATH/TO/figma-ui-mcp/server/index.js"
      ]
    }
  }
}
```

Replace `/ABSOLUTE/PATH/TO` with the real clone location, then fully quit and reopen the MCP client.

## 4. Register the Figma development plugin

1. Open Figma Desktop.
2. Go to **Plugins → Development → Manage plugins in development**.
3. Remove any older **Figma UI MCP Bridge** entry that points to a download folder or npm cache.
4. Select **Import plugin from manifest**.
5. Choose:

   ```text
   /ABSOLUTE/PATH/TO/figma-ui-mcp/plugin/manifest.json
   ```

6. Open a Figma design file.
7. Run **Plugins → Development → Figma UI MCP Bridge · Kiettt8**.

The plugin should show the custom light UI and move from **Connecting** to **Connected** when the MCP server is running.

## 5. Verify the connection

Ask the MCP client to call:

```text
figma_status
```

A working connection reports:

- `pluginConnected: true`
- Bridge port `38451`, unless a different port was selected.
- Information about the open Figma file.

If the plugin remains disconnected, confirm the bridge process:

```bash
lsof -nP -iTCP:38451 -sTCP:LISTEN
```

On Windows, use:

```powershell
netstat -ano | findstr :38451
```

## 6. Develop the custom UI

The Figma popup UI is:

```text
plugin/ui.html
```

After editing it:

1. Close the running plugin popup.
2. Run the development plugin again from Figma.

No build command is required for changes made only to `plugin/ui.html`.

The custom UI uses a compact semantic design language:

- Brand primary: `#0033C9`
- Primary text: `#001F3E`
- Supporting text: a contrast-adjusted blue-gray
- Base and subtle surfaces: `#FFFFFF` and `#F5F9FF`
- Semantic success, warning, danger, and info states
- SF Pro/system typography
- 8–12 px component radii
- 44 px compact controls

## 7. Develop plugin logic

Edit source files under:

```text
src/plugin/
```

Then rebuild the generated Figma main-thread file:

```bash
npm run build:plugin
```

Do not edit `plugin/code.js` directly. It is generated by `scripts/build-plugin.js`.

For automatic rebuilds on Node versions that support `--watch-path`:

```bash
node --watch-path=src/plugin --watch-preserve-output scripts/build-plugin.js
```

After rebuilding, close and rerun the Figma development plugin.

## 8. Develop the MCP server

Server files are under:

```text
server/
```

After changing server code:

1. Fully quit the MCP client.
2. Confirm that its previous server process has stopped.
3. Reopen the client so it launches the updated local source.
4. Rerun the Figma plugin.

## 9. Troubleshooting

### The old dark UI still appears

Figma is registered to a different manifest.

1. Open **Manage plugins in development**.
2. Remove the old plugin entry.
3. Import `plugin/manifest.json` from the current Git clone.
4. Close and rerun the plugin.
5. If necessary, fully quit and reopen Figma Desktop.

### The MCP client still runs the npm version

Replace a configuration like:

```json
{
  "command": "npx",
  "args": ["figma-ui-mcp"]
}
```

with the absolute local `node server/index.js` configuration from step 3.

### Port 38451 is already occupied

Inspect the process before stopping anything:

```bash
lsof -nP -iTCP:38451 -sTCP:LISTEN
```

Close the MCP client that owns the old process, or select another bridge port from the plugin UI.

### Figma is connected but commands go to the wrong file

Close unused plugin instances or pass the correct `sessionId` when multiple Figma files are connected.

## 10. Security notes

- Do not expose port `38451` directly to the Internet.
- The bridge endpoints do not provide production-grade authentication.
- Use this edition as a local development bridge.
- Apply firewall or loopback binding controls before using it on an untrusted network.
- Review every AI-generated write operation before using the plugin on production design files.

## 11. Review updates from the original project

This is a standalone repository derived from `TranHoaiHung/figma-ui-mcp`. It is not part of the original repository's fork network.

Configure the upstream remote once:

```bash
git remote add upstream https://github.com/TranHoaiHung/figma-ui-mcp.git
```

Fetch the original project's history:

```bash
git fetch upstream
```

Because the repositories have independent histories, review changes on a temporary branch instead of merging `upstream/main` directly into `main`. Select only the changes needed by this custom edition, preserve `plugin/ui.html` and `plugin/manifest.json`, then validate before pushing:

```bash
git switch -c review-upstream-update
# Apply and test selected upstream changes here.
npm run build:plugin
git switch main
git merge --no-ff review-upstream-update
git push origin main
```
